SQL-сценарий проверяет QR для двадцати учеников, повторную отметку, истёкший и поддельный код, неизменность подтверждения преподавателя, изоляцию школ, доступ только к связанным детям, запрет отметки родителем, отзыв полномочий преподавателя, блокировку аккаунта и отзыв веб-сессии. Отдельно проверены идемпотентная регистрация тревоги, принятие и закрытие, история, дедупликация очереди, аренды worker и отозванный доступ получателя перед отправкой.

Сквозная проверка прошла на настоящем production URL с отдельной временной Auth-фикстурой. Проверены парольный вход и Secure/HttpOnly/SameSite cookies, пустое состояние нового пользователя, сохранение своей школы с 3 группами и 60 фиктивными учениками, идемпотентная учебная тревога, повторное принятие, отказ запросам с чужим/отсутствующим Origin, выход и отказ скопированным до выхода cookies после отзыва сессии. Фиктивная школа, пользователь, сессии, ученики, уведомления и тревоги удалены точечным защитным cleanup; контрольные остаточные счётчики — 0.

В браузере ученик выполнил демонстрационную отметку по физике: в журнале появилось время самостоятельной отметки и статус «Не подтверждено». Затем преподаватель изменил статус на «Присутствует», появилось отдельное время подтверждения. QR-изображение успешно загрузилось в размере 400×400. Эти действия проверяют интерфейс локального демо; запись на настоящем сервере проверена отдельно HTTP- и SQL-сценариями.

Security Advisor: только 7 информационных сообщений `RLS Enabled No Policy` для намеренно закрытых таблиц `app_private`. Разрешающие политики не добавлялись. Performance Advisor после индексов: только `Unused Index` на новой базе. Подробности и ссылки на рекомендации — в `docs/DATABASE.md`.

## Границы результатов

- Тесты обработчиков используют подставной Telegram API. Реальный бот, доставка на телефон и получение сотрудником не проверены.
- Публичное демо использует только локальные вымышленные данные. Оно не является проверкой сохранения в Supabase.
- Настройка Auth Site URL/redirect и проверка реальных писем регистрации ещё не завершены: вход в панель Supabase потребовал CAPTCHA. Парольный вход подтверждённого пользователя проверен на production.
- Нагрузочный тест, восстановление резервной копии и эксплуатационный пилот в школе не проводились.
- Камера физического телефона и узкий мобильный viewport не проверялись в этой сессии; CSS содержит адаптивные правила.
- Интерфейс RU/KK переведён для основных разделов, статусов и действий; часть подробных пояснений пока на русском.

## Воспроизведение

```bash
npm ci
npm run typecheck
npm test
node --experimental-strip-types --test supabase/functions/_shared/worker.test.ts
npm run build
```

SQL-тест запускается администратором **только в отдельной тестовой Supabase-базе** после миграций. Он использует `BEGIN … ROLLBACK`, временные фиктивные Auth-записи и смену PostgreSQL-ролей. Это не команда для выполнения через браузерный publishable key.
