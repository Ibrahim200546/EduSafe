# EduSafe

**Посещаемость без остановки у входа, связь с представителями и координация помощи.**

**Опубликованный сайт:** https://edu-safe-alpha.vercel.app/  
**Демо без регистрации:** https://edu-safe-alpha.vercel.app/demo

Веб-приложение для школ и колледжей: Next.js + TypeScript на Vercel, Supabase Auth и PostgreSQL с RLS. Исходное ТЗ адаптировано к serverless: расписание и устойчивые задачи выполняются в PostgreSQL/Supabase, Telegram принимает webhook, постоянно работающий Python-процесс на Vercel не требуется.

## Возможности

- Лендинг, адаптивное пространство школы, русский и казахский интерфейс основных разделов.
- Регистрация, вход, подтверждение почты, восстановление доступа; серверные HttpOnly cookie.
- Отдельные организации, роли администратора, преподавателя, охраны, ученика и представителя.
- Группы, ученики, помещения, конкретные занятия, перенос и отмена.
- Общий динамический QR занятия (обновление 30 с, срок отдельного токена 60 с).
- Повторная отметка ученика идемпотентна; самостоятельная отметка отделена от подтверждения преподавателем.
- Ручной журнал для учащихся без телефона, опоздания, причины отсутствия и история изменений.
- Приглашения с ограниченным сроком, подтверждение и отзыв связей представителей; отдельное разрешение для взрослых учащихся.
- Тревоги с номером события, помещением, подтверждением ответственного, эскалацией и журналом обработки.
- Транзакционная очередь уведомлений, журнал тестовых отправок, подготовленная интеграция Telegram.
- Два разных режима демонстрации: публичный браузерный `/demo` и вымышленные учебные данные внутри собственной организации в PostgreSQL.

## Быстрый запуск на Windows

Нужны Node.js 22+ и Git. PostgreSQL используется в подключённом Supabase, локальный Docker для запуска сайта не обязателен.

```powershell
git clone https://github.com/Ibrahim200546/EduSafe.git
cd EduSafe
npm ci
Copy-Item .env.example .env.local
```

Укажите в `.env.local` URL **своего** Supabase-проекта и его publishable key. Публичный ключ работает только в рамках настроенных правил доступа. Секретный ключ и service role нельзя помещать в `NEXT_PUBLIC_*`.

```powershell
npm run dev
```

Откройте `http://localhost:3000`. Для демонстрации без регистрации: `http://localhost:3000/demo`.

Проверки и производственная сборка:

```powershell
npm run typecheck
npm test
npm run build
npm start
```

## Подготовка базы

SQL-миграции находятся в `supabase/migrations` и применяются по порядку к отдельному Supabase-проекту. Не выполняйте их поверх чужой рабочей базы. Для уже подготовленного проекта повторное применение не требуется.

Используйте подключённый Supabase CLI по его актуальной справке или SQL Editor. Логика предметной области находится в приватной схеме `app_private`, публичные RPC выполняют проверенные операции. Прямые записи браузерным ключом в таблицы запрещены.

После настройки откройте `/login`, зарегистрируйтесь и подтвердите почту. Создайте свою организацию или примите выданное администратором приглашение. При создании можно добавить 60 вымышленных учеников. Это отдельное пространство в базе; оно не даёт доступа к другим школам.

В Supabase **Authentication → URL Configuration** задайте адрес опубликованного сайта как Site URL и разрешите его callback `/auth/callback`. В настройках шаблонов писем/SMTP проверьте реальную доставку перед пилотом. Восстановление пароля использует этот же callback.

## Публикация на Vercel

Импортируйте репозиторий `Ibrahim200546/EduSafe`, выберите Next.js, корневая папка — корень репозитория.

Переменные Vercel:

| Переменная | Значение |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | URL отдельного проекта Supabase |
| `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | Publishable key того же проекта |
| `NEXT_PUBLIC_APP_URL` | URL опубликованного EduSafe |

Service role для веб-приложения не нужен. Маршруты работают с JWT текущего пользователя, а БД повторно проверяет членство и роль.

`vercel.json` задаёт Next.js и регион Frankfurt. Сначала проверьте целевые команду и проект, затем публикуйте. Для preview с реальными данными используйте отдельную среду и отдельный Supabase-проект.

## Telegram и фоновые задачи

По умолчанию внешние сообщения отключены. Для учебного сценария используется режим `mock`, результат виден в журнале уведомлений. Настройка реального Telegram, защищённого webhook и worker описана в [docs/TELEGRAM.md](docs/TELEGRAM.md) и [docs/OPERATIONS.md](docs/OPERATIONS.md).

Успех `sendMessage` означает принятие Telegram API. Реакция сотрудника фиксируется отдельной кнопкой «Принял». Возможный повтор внешнего сообщения после неопределённого сетевого результата документирован; логические события и записи посещения не дублируются.

## Камера и работа с телефона

На опубликованном HTTPS-сайте ученик открывает `/check-in` и разрешает камеру по запросу. Используется задняя камера и локальное распознавание QR; видеопоток не загружается на сервер.

Адрес `http://IP-компьютера:3000` позволяет проверить вёрстку из общей сети, но браузер может не разрешить камеру на таком адресе. Для камеры на телефоне нужен HTTPS. Исключение `localhost` относится к устройству, на котором открыт браузер, а не к любому компьютеру в сети.

Если камеры или телефона нет, учащегося отмечает преподаватель. Действующий QR можно переслать, поэтому самостоятельная отметка не заменяет подтверждение преподавателем.

## Ограничения учебного MVP

Это инструмент учёта и координации внутренних сигналов. Он не устанавливает непрерывное местоположение учащегося и не заменяет согласованный школой способ экстренного обращения. Отсутствие электронной отметки отображается как отсутствие подтверждения, а не доказанный прогул.

Перед реальными данными организация согласовывает порядок выдачи доступа, обработку и хранение данных, размещение, резервное обращение за помощью и ответственных сотрудников. Публичный `/demo` содержит только вымышленные данные; его изменения сохраняются в браузере посетителя.
