## Регистрация и первый вход

В текущей учебной публикации **Confirm email выключен**. Публичные настройки Supabase Auth возвращают `mailer_autoconfirm=true`; регистрация через production API проверена и возвращает `confirmationRequired=false`. После создания аккаунта пользователь сразу получает сессию.

Откройте `/login`, создайте аккаунт, затем создайте свою организацию или примите приглашение администратора. У нового пользователя ещё нет организации; это ожидаемый первый экран. При создании можно добавить учебный набор данных. Вход по паролю после выхода и чтение своего workspace также проверены на опубликованном сайте.

## URL и почтовые сценарии

В **Authentication → URL Configuration** сохранены и проверены в панели Supabase:

- Site URL: `https://edu-safe-alpha.vercel.app`.
- Redirect URLs: `https://edu-safe-alpha.vercel.app/auth/callback**`. Суффикс допускает параметры callback, включая `next`; разрешён конкретный домен опубликованного сайта.

Реальная доставка писем, настройка SMTP и восстановление доступа через письмо не проверялись. Для их использования требуется отдельная проверка шаблонов и доставки на согласованных тестовых получателях. Текущая регистрация не требует ожидания письма.

Справка: https://supabase.com/docs/guides/auth/redirect-urls

## Перенос в другой проект

Миграция 007 читает адрес назначения из Vault, без жёстко записанного project ref. В новой среде необходимо создать `edusafe_project_url`, случайный `edusafe_worker_secret` и зарегистрировать хеш последнего через служебную `edusafe_set_integration_secret('worker', ...)`. Только после этого задача HTTP начнёт вызывать Edge Function.

Код содержит отдельные учебные данные для публичного демо. Реальных данных учащихся при разработке не использовалось. Временная организация и Auth-фикстура сквозного HTTP-теста удалены после успешной проверки. Отдельный тестовый аккаунт, созданный при проверке регистрации, сохранён по запросу владельца без организации.
